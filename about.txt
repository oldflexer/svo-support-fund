🚀 Инструкция по запуску
Backend:
Создайте виртуальное окружение:

[bash]
cd backend
python -m venv venv
venv\Scripts\activate  # Windows

Установите зависимости:

[bash]
pip install -r requirements.txt

Запустите Flask сервер:

[bash]
python app.py

Frontend:
Откройте файл frontend/index.html в браузере

Или запустите через локальный сервер:

[bash]
# Установите http-server если нет
npm install -g http-server

# Запустите
cd frontend
python -m http-server -p 8080
Откройте http://localhost:8080

Откройте файл frontend/admin.html в браузере или запустите через сервер:

bash
cd frontend
python -m http.server 8080
Откройте http://localhost:8080/admin.html

🔒 Особенности реализации JWT
1. Двойная система токенов:
Access Token - короткоживущий (1 час) для доступа к API

Refresh Token - долгоживущий (30 дней) для обновления Access Token

2. Ролевая модель:
admin - полный доступ ко всем функциям

moderator - может управлять бойцами и пожертвованиями

viewer - только просмотр (можно добавить)

3. Защищённые маршруты:
@login_required - требует аутентификации

@role_required('admin', 'moderator') - требует определённых ролей

4. Безопасность:
Пароли хешируются с помощью bcrypt

JWT токены подписываются секретным ключом

Refresh токены хранятся в безопасных httpOnly куках (в продакшене)

Валидация паролей (мин. 8 символов, заглавные/строчные буквы, цифры)

5. Логирование действий:
Все действия администраторов логируются в AuditLog

Запись IP, user agent, времени и деталей действия

6. Автоматическое обновление токенов:
Frontend автоматически обновляет токены перед истечением срока

При 401 ошибке - автоматическая попытка обновления токена

📋 Преимущества такого подхода:
1. Централизованное управление схемами:
Все схемы в одном файле

Легко находить и изменять правила валидации

Единый стиль валидации для всего приложения

2. Повторное использование:
Схемы можно использовать в разных эндпоинтах

Можно наследовать и расширять схемы

3. Безопасность:
Автоматическая очистка от XSS

Валидация типов данных

Проверка граничных значений

4. Удобство поддержки:
Чёткие сообщения об ошибках

Легко добавлять новые поля

Поддержка как для JSON, так и для query параметров

Схемы легко тестировать отдельно от бизнес-логики

🔧 Рекомендации по использованию:
Всегда валидируйте входящие данные - даже если они приходят из "доверенного" источника

Используйте конкретные схемы для каждого типа запроса

Не забывайте про санитизацию - очищайте данные перед сохранением в БД

Обновляйте схемы при изменении моделей данных

🎯 Ключевые схемы в проекте:
LoginSchema - авторизация администраторов

AdminCreateSchema - создание администраторов (строгие требования к паролю)

FighterCreateSchema - создание/обновление бойцов

DonationCreateSchema - пожертвования (проверка суммы)

VolunteerCreateSchema - регистрация волонтёров

EquipmentRequestSchema - запросы снаряжения
